# /update-knowledge — еженедельный sync brain

**Никогда не пушить в основную ветку — только ветка + PR на ревью человеку.**
Агент из `team-os-agent` выполняет этот же регламент как duty «brain-sync»
(см. `robin/duties.md`).

## Шаги

1. **Обнови исходники:** `git pull` в репо знаний и в `CODE_ROOT`. Устаревший
   клон кода даёт ложные выводы («файл мёртв», «значения нет»).

2. **Прочитай неделю реальности** (что из этого доступно):
   - дайджесты чатов за 7 дней (стор агента, путь — в его конфиге);
   - закрытые задачи трекера за 7 дней (`<трекер>`; недоступен — отметь в PR,
     не падай);
   - `git -C "$CODE_ROOT" log --oneline --since='7 days ago'`.

3. **Обнови volatile-доки** (правь существующие файлы, новые — только если без
   них факт некуда положить):
   - `brain/now.md` — новый снапшот фокуса с датой и источниками;
   - `brain/product/object-model.md` — новые значения из кода, если чекер красный;
   - `brain/product/glossary.md` — новые термины недели (только с источником);
   - `product/features.md` — снапшоты статусов с датой.
   Во frontmatter изменённых файлов поставь `bot_updated: <сегодня>`.
   **`last_reviewed` не трогай** — его ставит человек на ревью.

4. **Прогони проверки:** `python3 brain/scripts/check_drift.py` — зелёный;
   `scripts/check-frontmatter.sh --all` — зелёный.

5. **Decision-mining:** новые эпизоды решений недели → записи `proposed` в
   `decisions.md`; принципы, которым неделя противоречила, — предложи amend или
   retire; подтверждения — допиши в «Подтверждения» принципа.

6. **Вопросы без ответа:** что спрашивали у агента и репо не ответило
   (`QUESTIONS.md`, лог агента) → предложи, куда добавить знание.

7. **PR:** ветка `brain-sync/YYYY-MM-DD`, описание «что изменилось и откуда
   узнал» по каждому файлу. Ревьюер — владелец brain (или «ревьюер недели»).
