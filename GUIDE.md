# Как устроен наш Team OS — гид для команды

> Что сюда писать: карта системы для человека, который видит её впервые. Ниже —
> готовый текст; поправьте имена (`<AGENT_NAME>`, `<TEAM_NAME>`), каналы и
> расписание под себя, а раздел «Статус» ведите честно.

## Идея в одном абзаце

Вместо того чтобы каждый раз спрашивать одного человека «есть ли фича X / как
работает Y / что бы ты решил», команда спрашивает **репозиторий знаний** —
напрямую агентом или через <AGENT_NAME> в чате. Репо отвечает с цитатой
источника; утверждения о коде сверяются с кодом при каждом коммите (враньё не
проходит хук); решения принимаются по датированным принципам, выросшим из наших
же эпизодов.

## Три слоя + агент

| Слой | Вопрос | Где | Что держит его честным |
|---|---|---|---|
| 1. Знания | «как что работает, кто за что отвечает» | `CLAUDE.md`, `product/` | frontmatter `owner / tier / last_reviewed`, граница доверия |
| 2. Brain | «какие на самом деле статусы, сущности, термины» | `brain/` | `claims.yaml` + `check_drift.py` в pre-commit |
| 3. Решения | «как мы решаем» | `decisions.md`, `skills/decide-like-team/` | вердикты agree/disagree на встрече |
| Агент | «голос системы» в чате | `soul.md`, `robin/duties.md` | ответы только с источником, duty по расписанию |

Агент — отдельный репо (бот в чате + duty по таймерам):
<https://github.com/slavkkoo/team-os-agent>. Этот репо — его память.

## Круговорот знаний

```
Чаты команды и клиентов ──▶ Дайджесты (duty 1) ──▶ память «что я пропустил»
        │                        │
        │                        ▼
        │                Brain-sync PR (duty 2) ──▶ product/, brain/now.md
        │                        │
        ▼                        ▼
  Разбор решений ──▶ decisions.md (proposed) ──▶ вердикт на встрече (duty 3)
                                 │                        │
                                 ▼                        ▼
                     skills/decide-like-team       ratified-принципы
                                 │
                                 ▼
     Вопрос тиммейта ──▶ агент ──▶ ответ из репо + сверка с кодом
                                 │       (drift-чекер не даёт докам врать)
                                 ▼
                 QUESTIONS.md (не ответили) ──▶ PR с пополнением
```

Чаты становятся дайджестами, дайджесты — знаниями, знания — ответами, споры —
принципами, а вопросы без ответа — задачами на пополнение.

## Как этим пользоваться

- **Вопрос «есть ли / статус / как работает»** — задайте <AGENT_NAME> в чате
  или откройте репо агентом (`claude` в корне репо). Ответ без источника — не
  ответ: попросите источник.
- **Агент ошибся** — скажите это в том же треде («на самом деле…»). Поправка
  уходит на ревью и становится знанием через PR.
- **Вопрос-решение** — сначала напишите свою рекомендацию и почему. Скилл
  `decide-like-team` сравнит её с принципами и покажет пробелы. Решает человек.
- **Хотите поправить репо** — ветка + PR. Хук проверит frontmatter и сверит
  brain с кодом.

## Что происходит само (если подключён агент)

Расписание — в [`robin/duties.md`](robin/duties.md). Типовой набор: ежедневный
дайджест чатов, еженедельный brain-sync PR, список pending-решений перед
встречей, еженедельный «голос клиентов». Упавшая duty обязана прислать алерт —
тишина не означает «выполнено».
