## Как отвечать (правила для агента)

1. Сначала `brain/now.md` — текущий фокус. Старше 14 дней — предупреди, что
   снапшот устарел.
2. Открывай только нужные файлы по оглавлению ниже, не читай всё подряд.
3. **Каждое утверждение — с источником:** путь файла в репо, номер задачи,
   ссылка. Нет в репо — скажи «в репо этого нет», не выдумывай.
4. Репо и система записи (код, трекер, CRM) разошлись — права система записи.
   Покажи обе версии и предложи поправку в репо.
5. Вопрос-решение («делаем X или Y?») — через `skills/decide-like-team/`.
   One-way doors из `decisions.md` — только бриф для эскалации, не решение.
6. Учитывай свежесть: `tier` и `last_reviewed` во frontmatter каждого файла.

## Граница доверия: что НЕ попадает в репо

Репо читают агент и вся команда, история git вечна. Поэтому сюда **никогда**
не пишем:

- **Зарплаты**, бонусы, условия найма и увольнения.
- **Персональные данные клиентов**: имена, телефоны, email, адреса, переписку.
  Примеры из тикетов — только обезличенные.
- **Коммерческие условия в цифрах**: цены по договорам, скидки, тарифы
  конкретных клиентов, выручку по клиентам. В репо — только указатель:
  «тарифы клиента — в CRM, карточка клиента, раздел "Договор"».
- **Секреты**: токены, пароли, ключи, строки подключения. Только «где взять».
- **Живое состояние**: статусы задач, текущие метрики. Только датированный
  снапшот + ссылка на систему, где живёт актуальное.

Можно: роли и зоны ответственности команды, рабочие контакты (по согласию
людей), процессы, решения с их причинами.

## Конвенции

- **Frontmatter** у каждого `.md` (pre-commit хук не пустит без него):
  `owner` — кто отвечает за правду в файле; `tier` — `stable` (верь),
  `evolving` (верь, но сверяй с источником), `volatile` (старше 14 дней —
  дисконтируй); `last_reviewed` — дата ревью **человеком**.
- **Боты и конвейеры не трогают `last_reviewed`** — они ставят `bot_updated`.
  Иначе дата перестаёт значить «человек проверил».
- **Изменения — только через PR.** Агент и конвейеры пушат ветку и открывают
  PR, в основную ветку не пишут.
- **Один файл — одна тема.** Файл разросся (больше ~15 КБ или несколько тем) —
  разбей по разделам и заведи `INDEX.md` в папке. Агенту дорого читать свалку.
- Имена файлов — kebab-case. Статусы и сроки — всегда с датой снапшота.
